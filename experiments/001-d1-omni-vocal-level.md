# 001 — d1-omni-600M, уровень вокала (первая точка аудиограммы)

Дата: 2026-10-16. Модель: `LiquidAI/d1-omni-600M-GGUF:Q8_0`, llama-server
0.7.0, CPU Mac. Данные: MUSDB18-7s (3 трека). Результаты:
`experiments/001-vocal-level.json`.

## Что делали

- T1 (абсолютный): шкала «far too quiet … far too loud» при сдвиге
  вокала −9…+9 дБ, все варианты выровнены по LUFS.
- T2 (2AFC): склейка «эталон | бип | испорченный» в обоих порядках,
  сдвиги ±6 дБ.
- Sanity: «что за запись» — music, p=0.99 (аудио доходит нормально).

## Результат: глухая

- T1: score 1.7–2.1 при любом сдвиге (−9…+9 дБ). Spearman ρ=0.32,
  p=0.16 — монотонной связи нет. Для всего отвечает «balanced».
- T2: 6/12 верных = уровень случая. **Во всех 12 ответах выбран «first»**
  — тотальный позиционный перекос (primacy bias), о каком бы сравнении
  ни шла речь.
- Проверка «пола»: вокал выключен совсем vs живой → P(вокал слышен)
  = 0.14 vs 0.21 — не различает даже наличие вокала.
- Экстремум ±12 дБ в 2AFC: снова «first» во всех 6 случаях (conf 0.49/0.41
  по порядку — детерминированно).

## Вывод

d1-omni-600M (speech-тюнинг) для микс-судейства бесполезна без
дообучения: не слышит уровень вокала в музыке вообще, ни в абсолютной
шкале, ни в сравнении. Это ожидаемо по карточке (запросы «спикер↔
ассистент»), подтверждено измерением.

Оставляем как бейзлайн «нижней границы». Если доучивать — только на
песочнице с нуля, либо как калиброванный эталон «до обучения».

## Замеченное про инфраструктуру

- llama.cpp помечает audio input в decision-моделях как experimental.
- Клиент: `judge.py` (POST /v1/systemone, wav → base64 data URL).
- Рендер: `render.py` (RBJ bell/shelf/HPF, LUFS через pyloudnorm,
  моно, ресемпл 16 кГц) — selftest зелёный.
