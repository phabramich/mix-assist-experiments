# 002/003 — AudioJev на Modal, уровень вокала (первая слышащая модель)

Дата: 2026-10-16. Модель: `shlv/AudioJev` (~5B, bf16) на Modal L4 через
`SihanLv/AudioJev-Inference` (`audiojev-serve`, тот же `/v1/systemone`).
Деплой: `modal_audiojev.py` →
`https://phabramich--mix-assist-audiojev-serve.us-east.modal.run`,
веса кешируются на volume `mix-assist-hf`, `scaledown_window=1800`.
Данные: `experiments/002-audiojev-vocal-level.json` (±9 сетка),
`experiments/003-audiojev-jnd.json` (мелкая сетка ±1.5),
контроль специфичности — инлайн-прогон ниже.

## T1 (абсолютная шкала уровня вокала): СЛЫШИТ

- Сетка −9…+9 дБ, 3 трека: **Spearman ρ = 0.80, p < 0.0001**. Монотонный
  рост score 1.6–2.2 → 2.6–2.8.
- Мелкая сетка ±1.5 дБ: ρ = 0.65, p = 0.0002. Шаги по 1.5 дБ дают
  сдвиги score ~0.05–0.15 — на уровне шума одного запроса.
  **Одиночный запрос надёжно различает ~±3–4.5 дБ**; ниже — нужны
  повторы/усреднение или больше треков.
- Ответ сжат и асимметричен: score насыщается около 2.7–2.8
  («a bit loud»), «far too loud» почти не выдаёт; у разных треков разный
  базовый уровень (нормально — в цикле работаем с дельтами).
- Легенда шкалы возвращается в `legend`, score помечен
  `experimental: true` (пометка авторов API).

## Контроль специфичности: score — про вокал, не про громкость

| Трек | Крутим drums −9…+9 | Крутим vocals −9…+9 |
|---|---|---|
| NightOwl | 2.16, 2.0, 1.9, 1.9, 1.97 (нет тренда) | 1.62 → 2.77 монотонно |
| Clinic A | 2.77 → 2.59 (слабый обратный дрейф) | 2.16 → 2.77 монотонно |

При уровнях, выровненных по LUFS, вопрос «vocal level» реагирует именно
на вокал. Лёгкое обратное движение при росте drums даже разумно
перцептивно (вокал относительно тише).

## T2 (2AFC-склейка «половина|бип|половина»): СЛОМАН — не использовать

- 6/12 = случай; **все ответы «second»** независимо от порядка.
- Убийственная деталь: conf/probabilities T2 **побайтово повторяются
  на разных треках** (0.0671/0.3951/0.6433/0.2745) — аудио не влияет,
  модель отвечает на текст. В их промпте «the half after the beep»
  сортируется в опцию A (criteria сортируются по тексту, см.
  `api.py:89`) — классический перекос на первую опцию.
- У d1-omni было зеркально то же самое (всегда «first»).
- Вывод: парадигма «сравни две половины одного клипа» для Jev-моделей
  не работает. Замены: сравнение T1-score между клипами (работает),
  noul-вопросы на отдельных клипах, мультиклип-state у Sori (до 8 клипов
  в одном state — ждём доступ), либо отдельный запрос на кандидата.

## Инфраструктура

- `judge.ask_audiojev(server, clip, context, questions)` — state =
  `{"audio_base64": ...}`, контекст сливается в instructions.
- `probe.py --judge audiojev --server <url>`.
- Порядок опций choice/noul сортируется по тексту описаний
  (ключам соответствие сохраняется — читаем probabilities по ключам).
- Для score заявлен диапазон 2–10 градаций.
- Стоимость прогона: копейки (L4 ~$0.8/час, запросы ~1–3 с).

## Что это меняет

Пара-петля «рендер кандидатов → Jev-score → сужение диапазона»
становится осмысленной: есть реальный измеритель с JND ~3–4.5 дБ на
уровень вокала. Для Stage-1 контроллера: бинарный/тернарный поиск по
шкале score с усреднением повторов на мелких шагах.
