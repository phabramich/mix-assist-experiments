# 012 — Агент миксует сырую сессию (LizNelson_Rainfall RAW)

## Постановка

Сессия `sessions/rainfall_raw`: 5 сырых моно-каналов из MedleyDB Sample
(vox_a/b/c, gtr_ac, gtr_el), unity gain, без обработки. Задача субагенту:
свести до разумного баланса полным набором mixctl-инструментов. Референс
инженера в `reference/` агенту был запрещён до отчёта.

## Что сделал агент

- Сам построил DSP-анализ поверх инструментов: f0-автокорреляцией по окнам
  определил роли — vox_a лид (все секции), vox_b верхняя гармония терцией
  (только припевы), vox_c низкий дабл-подложка (97% энергии в lowmid).
- Нашёл реальную проблему: в припеве лид был на 4.4 дБ *под* своей гармонией.
- Финальные knobs: vox_a +4дБ/pres+2/shelf+2, vox_b −3, gtr_ac −1/−3@280Hz,
  gtr_el +5, HPF на всём. Рендер `/tmp/rainfall_agent_mix.wav`.

## Верификация против референса инженера

| | agent | ref |
|---|---|---|
| LUFS | −19.9 | −23.0 |
| sub | 0.133 | 0.206 |
| lowmid | 0.747 | 0.708 |
| mid | 0.110 | 0.076 |

Направление верное (лид слышен, маскировка снижена), вкус отличается:
агент сделал форвард-лид и подрезал sub сильнее инженера; микс горячее на
3 дБ (нет master-ручки).

## Найденные проблемы поверхности (главный выход эксперимента)

1. **`fix` не работает на не-семантических именах стемов.** Вопрос про
   «vox_a» судья не резолвит → runaway (score даже падал на +11дБ).
   Нужны имена-слова (vocals/guitar) или описание трека в контексте.
2. **Судья EQ-слеп:** ±6 дБ гейна, HPF+bell — дельты <0.1. EQ-решения
   верифицируются только метрами, не ухом модели.
3. **Приминг-галлюцинации:** при стеме на −60 судья уверенно (0.92)
   «слышит» то, что написано в вопросе. Вопросы не должны подсказывать
   ожидаемый ответ; контрольный кейс с заглушенным стемом — must have.
4. **Окно судьи = 12 с вокруг пикового RMS** — судит только припев;
   куплеты экстраполированы по LUFS.
5. **Нет master gain** — общий уровень не подкрутить.
6. meters LUFS стерео vs mono ~3 дБ расхождение — учитывать при сверке.

## Выводы

Поверхность выдержала реальную задачу, но судья надёжен только для
грубых уровней (громче/тише лида на 4+ дБ), не для тонкой работы.
Приоритетные фиксы: семантические имена/описания стемов в STATE,
master-ручка, анти-приминговый дизайн вопросов.
